# 结构层

两镜以上（三联、九镜、自定义格数）才读本文；单帧任务只取「单帧三问」即可。

上游：导演决定书（带来节拍偏好）；下游输入：一份镜头清单。本文只解决「一段故事怎么切成若干颗镜头」，单镜机位与光色交给摄影层、光色层。

## 故事合同

动笔前先和用户对齐改编权限，三选一：逐字忠实 / 授权改写 / 开放命题自由发挥。给了完整故事就默认忠实；只给一句开放命题，允许原创，但要划清哪些来自用户、哪些是新增设计。

登记格式：

```
事实清单 F1/F2/…：人物关系、先后顺序、用户指定的镜头、既定结局
必须拍到：光靠文字交代不算数的事件与结果
可补拍：为衔接服务的接近、驻足、注视、接物
不可动：动机、身份、资源数量、结局
对照表：每条事实 → 承载它的镜号；补拍镜注明自己承担什么
```

警惕模板病：别拿「发现—牺牲—反转」去覆盖用户本来安静的日常或已经写死的结局。两份锚帧彼此打架时，把冲突摆上桌面，不要私造第三个事件来抹平。

## 拆法预设

从下列预设里挑一个，换预设要写一句理由；不许即兴发明新结构。切分颗粒度优先服从导演决定书的节拍偏好。

**单帧三问**（不建清单）：

```
这颗镜头拍哪一件事：只许一件
谁在看：机位替谁站着
观众看完该带走什么信息
```

**三联**（功能是默认值，可调整，别当硬性配额）：

| 位 | 默认职责 | 可替换方向 |
|---|---|---|
| 首格 | 交代世界与距离感 | 倒叙：先给结果再回起因 |
| 中格 | 用一个看得见的动作推进关系 | 以关键物件特写充当转折 |
| 尾格 | 收余韵：反应、延续或空场 | 画外暗示、留白收束 |

拼版时的高度配比选项统一放 delivery.md 维护。

**九镜**（按锚点切，不是九连转折）：

每个故事锚点切成「前因—动作—结果」三拍；三个锚点 × 三拍即九镜。三联升九镜同理细化，不强行塞反转或开放尾巴。原创冲突戏可参考候选链条「建立—发现—证据—压力—决定—变化—后果—代价—余韵」，但链条里没有一项是必选项。日常、抒情、产品、纪录类题材：观察、接近、互动、停留就够，不为凑满九格硬造事件。

**任意格数**（四格、六格等）：锚点数 × 拍数做升维降维——四格 = 两锚（事件/余波）× 两拍（动作/结果），或建置/POV/揭示/顶点四个功能位；六格 = 两锚×三拍或三锚×两拍。账本里必须写一句为什么这么拆；禁止为凑数强加事件。排布方式见 delivery.md。

验收按固定次序，硬门槛永远在前：事实覆盖 → 相邻衔接 → 跨镜因果 → 实体守恒 → 事件可读；之后才轮到节奏、构图、色彩。

## 镜头清单

生成前建好，列按需保留：

```
镜号 | 承载事实 | 职责 | 镜前→事件→镜后 | 实体状态 | 机位/拍向/轴侧 | 风格期 | 可见证据 | 依赖镜 | 出场角色ID
```

多角色任务加「出场角色ID」列，与 grid.md 角色注册表对齐：该镜有谁、各自状态（在场/画外/被遮挡）。B 轨网格直出时，账本每行对应一格，格序 = 左上到右下读序。

一颗静帧只冻结动作的一个切片。只有验收过的状态才有资格流给下游当参考；提示词写得再好，也不等于动作已经生成成功。

### Base Lock + Shot Delta（连续系列专用）

系列任务不逐镜从零设计。先立一份 **Base Lock**（系列圣经），此后每镜只写 **Shot Delta**（相对上一叙事状态的增量）：

- **Base Lock 收纳**：角色锁（脸型/年龄/体型/发型/惯用手——身份锚点不含临时表情与姿势）、服装锁（款式/剪裁/面料/合身度/鞋靴；湿、脏、破损、脱下按时间线逐镜登记）、道具锁（尺寸/持握方式/朝向/状态，易主走 Delta）、场地拓扑（门洞/窗/柱/家具/机位可达带；世界的左右远近不随机位漂移）、光圣经（固定光源/时序推进/色污染/曝光逻辑，不为单帧好看而重新布光）、机位圣经（见证位允许带/景别带/焦段行为/遮挡习惯/禁用英雄构图）、风格期与档位（全系列共用一条 lock，中途不换链）
- **Shot Delta 只登记**：本镜动作、表情、机位在圣经坐标系里的位置、道具服装的状态推进、天气时间推进，以及随之必然发生的物理后果（手被占用、水渍、影子方向、可见性变化）
- **每镜编译 = Base Lock + Delta**，从同一份中间表示出发，逐镜不另起炉灶
- **输出前过禁漂移清单**：身份变形、服装重设计、拓扑漂移、道具复制、光源搬家、风格换期、机位英雄化

### 实体状态

可脱下、可损坏、可交换的衣物道具一律按状态管理，不焊死在身份上。长得一样 ≠ 可以凭空变出第二件。数量服从已建立的事实。

```
镜号 | 实体 | 镜前 | 事件 | 计划镜后 | 实际观察 | 结论
5    | U1伞 | A持有、闭合、1把 | B接住、A松手 | B独持、A空手 | 生成后填 | 未验证
```

交接核对三件事：接收方是否独持；交出方是否真松了手、有没有还戴着第二件；双方同时接触的那一瞬仍算同一件实体。

画外、被挡、镜中倒影、屏幕里的像，各自打标记。常规继承前一镜的结果；跳时、归还、修复、闪回必须登记对应事件——没有事件就不许自动复原。

会推动剧情的信息另记一笔：谁此刻已经看见/知道了什么，防止角色提前做出还不该有的反应。

## 具象化

先分清「要的是意象」还是「要的是可辨认角色」。用户点名某角色出场时，烟雾、剪影或路人都不能顶替。

化形三阶段：未显现 → 半成形 → 可辨实体。进度服从剧情，不强制每镜往前挪一步。实体化之后要消散或复原，同样需要剧情依据。

两条分开验收：① 角色认得出来；② 化形来源读得懂。静帧能呈现阶段，证明不了完整时间过程。

用户反馈「我看不到那个角色，只有一团模糊意象」时，先按缺失处理，别反转成「禁止角色登场」。若两种理解会引向不同结局，先问一句再动手。

## 生成推进

1. 备齐必要参考。已批准且状态无误的镜头直接保留，不回炉。
2. 沿依赖链推进，可三镜一组；发生转移/损坏的镜头优先验收。
3. 只把验收过的状态传下游。不用第一镜的初态母版压住后续状态，也不链式引用错误帧。
4. 失败只修那一镜，再复查依赖它的后继。自动补跑次数遵守主文件上限。
5. 源图齐了再做外部拼版。

分几批、文件多少，都不是连续性成立的证据。

## 验收

1. 事实覆盖：关键事实都有画面证据；新增内容没有偷换原意。
2. 相邻衔接：接物、走近、进出门口、视线朝向彼此相容。
3. 跨镜因果：第 5 镜交出去的腕带，到第 9 镜那只手腕必须还是空的。
4. 实体守恒：增减或复制要有剧情依据；倒影不构成第二个角色。
5. 事件可读：没拍出来的动作，不能靠配文补写。

每项记 通过 / 失败 / 无法判断，附证据。手腕没看到，就不能宣布「裸腕通过」。
