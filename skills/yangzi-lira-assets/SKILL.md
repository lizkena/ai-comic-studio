# 洋子 · Lira 生图（工作台适配）

依据 AI STUDIO 洋子 V3.3.1 的 film-lira-assets；原始规范与变更控制保存在 references。使用用户当前选择的模型与渠道，不自动切换模型或要求安装课程工具。

## 调用约定

- 只返回调用方规定的 JSON 字段。生图前编译返回 prompt 字符串；批量提示词任务保留每个目标 id 与 image_prompt。视频字段由视频/分镜规则负责，不把本规范用于配音。
- 不输出分析过程、4D 标题、操作说明、磁盘路径或交互菜单。生成的提示词本身是一段自然的画面描述，不把 SKILL.md 整段交给生图模型。
- 用户修改要求、已确认资产与原文事实优先于示例。画风遵循当前项目：动画维持动画，写实才使用摄影和真实材质，不能把所有作品强制改成真人片。

## 内部执行 Lira 4D

1. 解构：确定目标是人物设定图、空场景、道具还是镜头首帧；读取身份、时代、服装状态、物件、地点与用户指定更改。
2. 诊断：消除人物混用、空间矛盾、光向冲突与过量动作。参考图只有在真正传给图像模型后才作为图像依据；文字编译未看见图片时不得声称检查过其细节。
3. 开发：按主体身份与状态 → 静态姿势和构图 → 前中后景空间 → 光线与材质 → 项目画风组织描述。用具体空间锚点、相对位置、真实光源和统一色彩，避免抽象美学词堆砌。仅引用输入已有信息，不无依据更换脸、年龄、服饰或建筑。
4. 交付：输出紧凑、自然、清楚的中文画面描述，通常约 150–600 字，复杂画面以必要信息为限。画幅、分辨率交由 API 参数，不用提示词中的尺寸代替参数。

## 按目标区分

- 角色资产：同一人保持稳定身份 ID，年龄、服装、伤痕等作为状态版本。描述脸型、发型、体态和指定服装，背景简洁。仅用户要求人物设定卡时做多视图；不要让普通角色图默认变成多人拼贴。
- 场景资产：人物数量遵循用户要求，空场景保持为空；固定门窗、道路、地标、深度、机位和光源方向，供后续镜头复用。
- 道具资产：明确形状、材料、尺寸关系、磨损与当前状态，使用易辨识的简洁背景；不能用换物件来表达同一道具的状态变化。
- 分镜首帧：只描绘镜头起始时的一个瞬间、一个视角；使用 start_pose（有提供时）和起始动作状态，不把动作结尾当首帧。保留关联角色、场景和道具身份。不得加入对白、旁白、音效、运镜时间线、连续多格、分镜联系表或多角度角色卡。
- 局部更改：先指定更改内容，再明确保留身份、服装、场景布局、机位和光色。已有图确需作为编辑依据时通过图像参考接口传入，不能仅在文字中声称保留。

避免额外字幕、说明文字、界面、水印与品牌标识；确有文字道具时只要求输入给定的文字，不保证生图模型能准确排版，不能自创一段剧情文字。少用长串否定词，以清晰的目标画面为主。
